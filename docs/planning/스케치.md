# 목표
## 모드 기반(장르 혼합) 게임 구조

하나의 게임 안에서 “모드(규칙/입력/UI)”를 교체하며 장르가 자연스럽게 바뀌는 경험을 만든다.

## 월드/플레이 계층

### InGame 레벨

- Chapter(유적/탐험 단위, 여러 방 묶음)

- Stage/Room(방, 단일 컨텐츠 단위)

방(Room)에서 바뀌는 것 = “모드”

전투(클릭 타겟 제거/딜)

슈팅(커서 방향 발사)

디펜스(웨이브)

타이머 퍼즐(물/불 도망)

커맨드 배틀(입력 커맨드 기반)

잠입

etc

## 핵심 시스템 스케치
### 1. Mode 시스템(게임의 뼈대)
#### Mode가 책임지는 것

- 입력 규칙(클릭=타겟/발사/상호작용 등)

- 승패 조건/정산

- 룸 HUD 요소(타이머, 목표, 게이지, 크로스헤어 등)

- 룸 전용 리소스/룰

#### 구현 형태

- UGameplayModeHandler(인터페이스/베이스 클래스)

  - Enter(Context)

  - Exit()

  - OnPrimaryClick() / OnSecondaryClick() / OnCommandInput()

  - TickMode(Delta)

  - GetHUDLayoutId() 또는 GetHUDFlags()

- 모드 선택은 StageDefinition(DataAsset)로:

  - ModeHandlerClass

  - 입력 맵핑(IMC)

  - 룸 목표/타이머/난이도

  - 룸 보상/정산 규칙

> 포인트: 클릭 입력이 “어디로 가는지”를 Mode가 결정한다.
(Actor 클릭을 쓰든, 커서 방향 Trace든, 발사든 다 여기에 캡슐화)

## 2. Economy(재화) 스코프: Meta / Chapter / Room

### A) Meta(영구) — Save에 남는 것

- 영구 업그레이드(모든 챕터/스테이지 공통)

- 해금(무기/스킬/모드 접근)

- 전역 통화(필요하면)

### B) Chapter(챕터/탐험) — 유적 탐험 한 번 동안

- 챕터 전역 버프/아이템(방을 넘어 유지)

- 챕터 재화(방들에서 모아 챕터 중간 상점/제단에서 소비)

- “이번 탐험에서만 의미 있는 성장”

### C) Room(방/스테이지) — 방 안에서만

- 제한 시간, 퍼즐 카운트, 방 전용 에너지/점수/콤보

- 방 끝나면 리셋되거나 정산 후 상위 스코프로 전환
